**Empty vs unknown:** These are different from the sensor **state** string.

- **`empty: true`** — no usable spool (slot empty, feeding, or RFID scan in progress).
- **`empty: false`, `unknown: true`** — spool is present but not configured (`?` on the printer). Typical after inserting an unprofiled spool or using **Clear** in filament settings while the spool stays loaded.
- **`empty: false`, `unknown: false`** — spool present with a correct profile.
</Info>

### External AMS heater (SUNLU AMS Heater)

Add-on heated lids such as the [SUNLU AMS Heater](https://store.sunlu.com/products/sunlu-ams-heater-upgraded-your-bambu-ams-save-an-ams-2pro-for-you) have no network connection and never report to the printer. ha-bambulab can still run one by switching the smart plug it is powered from, using the AMS's own humidity and temperature readings.

To set it up, plug the heater into a smart plug that Home Assistant can switch, and set the heater to start heating whenever it gets power. Then open the integration's **Configure** dialog, pick **External AMS heater (smart plug)**, and choose the plug for each AMS that has a heater fitted. These entities are added to that AMS:

| Entity                    | Notes |
| ------------------------- | ----- |
| Heater drying mode        | While on, the plug is switched automatically. Turning it off switches the heater off and hands the plug back to manual control. Attributes: `heater_plug`, `last_reason`, `runtime_lockout`. |
| Heater power              | Mirrors and switches the plug. While drying mode is on, the next printer update can override a manual change. |
| Heater turn-on humidity   | Heating starts at or above this AMS humidity (default 40%). |
| Heater turn-off humidity  | Heating stops at or below this AMS humidity (default 25%). Must be lower than the turn-on humidity. |
| Heater temperature cutoff | The heater is switched off while the AMS temperature is at or above this (default 60 °C). Only added when the printer reports AMS temperature. |
| Heater maximum runtime    | The heater is switched off after running this long (default 12 h, 0 = no limit). It then stays off until the AMS dries to the turn-off humidity or drying mode is switched on again. The runtime is counted from when the plug last turned on, so a Home Assistant restart or the plug dropping offline restarts the count. |

The heater is also switched off whenever the printer is offline, the AMS humidity isn't reported, the plug is unlinked, or the integration is unloaded while drying. Automatic control needs the AMS **Humidity** sensor in percent, listed above. The heater's own thermostat still sets its heating temperature.

## MakerWorld

A MakerWorld profile belongs to the same Bambu Lab account the cloud connection
already signs into, so these are created automatically when the integration is
set up with Bambu credentials and the account has a MakerWorld profile. They
live on their own `MakerWorld (<name>)` device rather than on a printer, and are
polled every 15 minutes.

| Sensor           | Notes                                                                 |
| ---------------- | --------------------------------------------------------------------- |
| Points           | Your points balance, as shown on the MakerWorld points page            |
| Points earned    | Lifetime points earned - use this one for daily/monthly statistics     |
| Boosts received  | Boosts your models have been given, all time                            |
| Boost tokens     | Boost tokens currently available to give out                           |
| Downloads        | Downloads of your models, the figure your profile page shows           |
| Prints           | Prints of your models, the figure your profile page shows              |
| Published models | Number of models you have published                                    |
| Likes            |                                                                       |
| Collects         |                                                                       |
| Followers        |                                                                       |
| Level            | Attributes contain the profile name and URL                            |

The following are disabled by default - enable them in Home Assistant if you
want them: Points spent, Exclusive points, Boosts used, Boosts expired, Print
profile downloads, Print profile prints, Downloads incl. print profiles, Prints
incl. print profiles, Following.

<Info>
MakerWorld counts a print profile - which may sit on someone else's model -
separately from the model itself, and your profile page shows only the model
half. The default Downloads and Prints sensors match the page; the "incl. print
profiles" sensors add the other half, a figure MakerWorld does not display
anywhere.
</Info>

<Info>
With several printers on one Bambu Lab account these sensors are created once,
by whichever printer's config entry was added first - the numbers describe the
account, not a printer.
</Info>

<Info>
These come from the account's own MakerWorld profile, which needs the cloud
token. If that call is rejected the integration falls back to the public
creator profile, which carries the same counts but no points and no boosts -
those sensors then report unavailable while the rest keep working.
</Info>

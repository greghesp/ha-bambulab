# How to contribute

Want to contribute to ha-bambulab? Great! We have a few small asks though!

- Please create your pull requests against the `main` branch.
- Please be verbose in your description of your changes in your pull requests.
- Name your commits with a [Conventional Commits](https://www.conventionalcommits.org/) prefix (`fix:`, `feat:`, `docs:`, `chore:`) and describe the change the way a user would notice it.

ha-bambulab is split across two repositories:

| What you want to change | Repository |
|---|---|
| The integration: entities, actions, config flow, the printer connection | [greghesp/ha-bambulab](https://github.com/greghesp/ha-bambulab) (this one) |
| The dashboard cards | [greghesp/ha-bambulab-cards](https://github.com/greghesp/ha-bambulab-cards) |

# Integration Development

<Steps>
  <Step title="Clone this repo">
    ```bash
    git clone https://github.com/greghesp/ha-bambulab.git
    ```
  </Step>
  <Step title="Run the tests">
    ```bash
    tests/run_tests.sh
    ```

    This creates a fresh `.venv`. If you already have an environment with `tests/requirements_ha.txt` installed, `python -m pytest tests` does the same.
  </Step>
  <Step title="Lint your changes">
    ```bash
    python scripts/lint_changed_lines.py
    ```

    It only checks the lines your branch changes, so you won't be asked to fix older code. Add `--fix` to format those lines. It needs [Ruff](https://docs.astral.sh/ruff/) at the version pinned in `pyproject.toml`.
  </Step>
  <Step title="Open a pull request">
    Fill in the **Tested on** and **Evidence** sections of the PR template. Most changes depend on what one printer model reports, and reviewers usually don't have that printer, so the MQTT payload or debug log is what lets them check your change. Remove serial numbers, access codes and IP addresses first.
  </Step>
</Steps>

New user-facing text goes in `custom_components/bambu_lab/translations/en.json`. If you speak any of the other languages in that folder, you're welcome to add your own translations; anything left out is filled in later.

Using an AI coding agent? Point it at [AGENTS.md](https://github.com/greghesp/ha-bambulab/blob/main/AGENTS.md).

# Frontend Development

The cards are developed in [ha-bambulab-cards](https://github.com/greghesp/ha-bambulab-cards), not in this repository. Its [README](https://github.com/greghesp/ha-bambulab-cards#development) covers setup, the dev server and the project layout.

<Warning>
  Don't edit `custom_components/bambu_lab/frontend/ha-bambulab-cards.js` in this repository. It's the built bundle, and it's replaced automatically every time the cards are released.
</Warning>

In short:

<Steps>
  <Step title="Clone the cards repo">
    ```bash
    git clone https://github.com/greghesp/ha-bambulab-cards.git
    ```

    You need Node.js 20 or later.
  </Step>
  <Step title="Start the dev server">
    ```bash
    npm ci
    npm start
    ```

    This rebuilds on every change and serves the cards on port 4000. In a test Home Assistant, add a dashboard resource of type **JavaScript module** with the URL `http://<your-machine>:4000/ha-bambulab-cards.js`, and remove it when you're done.
  </Step>
  <Step title="Check the build">
    ```bash
    npm run build:strict
    ```

    CI runs this on every pull request, and it fails on type errors.
  </Step>
  <Step title="Open a pull request">
    Open it against `main` in ha-bambulab-cards. Report card problems on [ha-bambulab's issues](https://github.com/greghesp/ha-bambulab/issues?q=label%3Afrontend) with the **frontend** label.
  </Step>
</Steps>

## How card changes reach users

When a cards release is published, it opens a pull request here that copies the new build into `custom_components/bambu_lab/frontend/` and bumps the card version in `const.py`. Your change reaches users with the next ha-bambulab release after that pull request is merged.
